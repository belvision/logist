## Архитектурные решения

### ✅ Почему НЕ используем public/locales
1. **Производительность**: Прямые импорты быстрее HTTP запросов
2. **Надёжность**: Нет риска 404 ошибок
3. **TypeScript**: Лучшая поддержка типов
4. **Bundling**: Next.js оптимизирует импорты
5. **Современность**: Рекомендуемый подход в 2024

### ✅ Почему НЕ используем next-i18next
1. **Простота**: Публичные страницы не требуют SSR для i18n
2. **Client-side**: Достаточно клиентского рендеринга
3. **Гибкость**: Меньше ограничений и проще настройка
4. **Производительность**: Быстрее загрузка

### ✅ Почему Client Components
1. **Интерактивность**: Переключение языка требует useState
2. **LocalStorage**: Работа с браузерным API
3. **Простота**: Не нужны серверные компоненты для лендингов

## Как использовать

### Для разработчиков:
```bash
# 1. Переводы уже установлены и настроены
# 2. Просто используйте хук в компонентах
```

### Пример добавления перевода на новую страницу:

```typescript
'use client';
import { useTranslation } from 'react-i18next';

export default function MyPage() {
  const { t } = useTranslation();
  
  return <h1>{t('myPage.title')}</h1>;
}
```

### Добавление новых ключей:

1. Откройте `src/locales/ru/translation.json`
2. Добавьте ключ: `"myPage": { "title": "Заголовок" }`
3. Скопируйте в остальные 8 языков с переводом
