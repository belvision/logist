# Обновление логики поиска попутных грузов с поддержкой промежуточных точек

## Проблема
Ранее при поиске попутных грузов маршруты строились только по начальной и конечной точкам из колонок `departure_place_id` и `arrival_place_id`. Промежуточные точки, которые могут храниться в `departure_place_id`, не учитывались.

## Решение
Доработана логика в `companion_cargo.service.ts` для:
1. Парсинга промежуточных точек из `departure_place_id`
2. Построения маршрутов с учетом промежуточных точек
3. Сравнения маршрутов с учетом всех точек

## Структура данных

### Формат departure_place_id с промежуточными точками:
```json
{
  "2904648": {
    "lat": 53.9024716,
    "lon": 27.5618225
  },
  "waypoints": [
    {
      "place_id": 3083240,
      "lat": 52.7840567,
      "lon": 27.5420336,
      "name": "Солигорск, Солигорский район, Минская область, Беларусь"
    }
  ]
}
```

### Обратная совместимость
Если в `departure_place_id` нет поля `waypoints`, используется старая логика построения маршрута только по начальной и конечной точкам.

## Изменения в коде

### 1. companion_cargo.service.ts
- Добавлен парсинг `waypoints` из `departure_place_id`
- Обновлена логика построения маршрутов для учета промежуточных точек
- Улучшено логирование для отладки

### 2. cargo.schema.ts
- Обновлена схема валидации для поддержки структуры с `waypoints`

### 3. cargo_search.types.ts
- Обновлены типы TypeScript для поддержки промежуточных точек

## Алгоритм работы

1. **Парсинг данных груза:**
   - Проверяется наличие поля `waypoints` в `departure_place_id`
   - Извлекаются координаты промежуточных точек
   - Определяется основная точка отправления

2. **Построение маршрута:**
   - Создается массив всех точек: `[начальная, ...промежуточные, конечная]`
   - Строится маршрут через OSRM с учетом всех точек
   - Получается геометрия маршрута с промежуточными точками

3. **Сравнение маршрутов:**
   - Используется существующий алгоритм `calculateRouteMatchPercent`
   - Сравниваются геометрии основного маршрута и маршрута груза
   - Учитываются все промежуточные точки при расчете совпадения

## Тестирование
Создан тестовый скрипт для проверки парсинга промежуточных точек. Логика корректно:
- Извлекает промежуточные точки из JSON
- Строит правильную строку для OSRM API
- Сохраняет обратную совместимость

## Логирование
Добавлено подробное логирование для отладки:
- Количество найденных промежуточных точек
- Координаты всех точек маршрута
- Результаты сравнения маршрутов
- Процент совпадения с учетом промежуточных точек
