# Объяснение портов MinIO в конфигурации

## 🔍 Вопрос: Почему разные порты?

### В .env файле:
```
MINIO_ENDPOINT=io.logistgo.pro
MINIO_PORT=443
MINIO_USE_SSL=true
```

### В nginx конфигурации:
```nginx
location /logistic-pro/ {
    proxy_pass http://127.0.0.1:9000/;  # Порту 9000
}

location /console/ {
    proxy_pass http://127.0.0.1:9001/;  # Порту 9001
}
```

## ✅ Объяснение

### Схема работы:

```
Интернет (внешний доступ)
    ↓
    HTTPS :443 (io.logistgo.pro)
    ↓
nginx (reverse proxy)
    ↓
    ┌─────────────────┬─────────────────┐
    ↓                 ↓                 ↓
MinIO API         MinIO Console    Frontend
:9000             :9001            :3000
(локально)        (локально)       (локально)
```

### 1. Внешний доступ (порт 443)

- **Порт 443** - это внешний порт, доступный из интернета
- Через этот порт пользователи и приложение подключаются к MinIO
- URL: `https://io.logistgo.pro:443` (или просто `https://io.logistgo.pro`)

### 2. Внутренний доступ (порты 9000 и 9001)

- **Порт 9000** - локальный порт MinIO API (внутри сервера)
- **Порт 9001** - локальный порт MinIO Console (внутри сервера)
- Эти порты доступны только внутри сервера (127.0.0.1)
- nginx проксирует запросы с внешнего порта 443 на эти локальные порты

## 📋 Почему так сделано?

### Безопасность:
- MinIO порты 9000/9001 не открыты в интернет
- Доступ только через nginx (порт 443)
- nginx может фильтровать запросы, ограничивать доступ

### SSL/TLS:
- nginx обрабатывает SSL сертификаты
- MinIO работает без SSL локально (быстрее)
- Внешние запросы идут через HTTPS (443)

### Гибкость:
- Можно изменить порты MinIO без изменения внешних URL
- Можно добавить аутентификацию, rate limiting и т.д.

## 🔧 Как это работает на практике

### 1. Приложение (Backend) подключается к MinIO:

```typescript
// В .env указано:
MINIO_ENDPOINT=io.logistgo.pro
MINIO_PORT=443
MINIO_USE_SSL=true

// Приложение делает запрос:
https://io.logistgo.pro:443/logistic-pro/cars/image.jpg
```

### 2. nginx получает запрос:

```nginx
# nginx видит запрос на /logistic-pro/cars/image.jpg
location /logistic-pro/ {
    # Проксирует на локальный MinIO
    proxy_pass http://127.0.0.1:9000/;
    # MinIO получает запрос на /logistic-pro/cars/image.jpg
}
```

### 3. MinIO обрабатывает запрос:

- MinIO работает локально на порту 9000
- Получает запрос от nginx
- Возвращает файл обратно через nginx

## 🎯 Итоговая схема

```
┌─────────────────────────────────────────┐
│  Интернет / Пользователи                │
│  https://io.logistgo.pro:443            │
└─────────────────┬───────────────────────┘
                  │
                  ↓
┌─────────────────────────────────────────┐
│  nginx (порт 443)                       │
│  - SSL/TLS обработка                    │
│  - Маршрутизация запросов               │

┌─────────┐ ┌─────────┐ ┌──────────┐
│ MinIO   │ │ MinIO    │ │ Frontend │
│ API     │ │ Console │ │          │
│ :9000   │ │ :9001   │ │ :3000    │
│(локально)│ │(локально)│ │(локально)│
└─────────┘ └─────────┘ └──────────┘
```

## ✅ Правильная конфигурация

### В .env (для приложения):
```env
MINIO_ENDPOINT=io.logistgo.pro  # Внешний домен
MINIO_PORT=443                  # Внешний порт (HTTPS)
MINIO_USE_SSL=true             # Использовать SSL
```

### В nginx (для проксирования):
```nginx
location /logistic-pro/ {
    proxy_pass http://127.0.0.1:9000/;  # Локальный порт MinIO API
}

location /console/ {
    proxy_pass http://127.0.0.1:9001/;  # Локальный порт MinIO Console
}
```

## 🔍 Проверка

### На сервере проверьте порты:

```bash
# Проверьте, что MinIO работает локально:
sudo netstat -tlnp | grep 900
# Должны быть:
# tcp  0  0  127.0.0.1:9000  ...  minio  (API)
# tcp  0  0  127.0.0.1:9001  ...  minio  (Console)

# Проверьте, что nginx слушает порт 443:
sudo netstat -tlnp | grep 443
# Должен быть:
# tcp  0  0  ...:443  ...  nginx
```

### Проверьте доступность:

```bash
# Локально (на сервере):
curl http://127.0.0.1:9000/  # MinIO API
curl http://127.0.0.1:9001/  # MinIO Console

# Извне (через nginx):
curl https://io.logistgo.pro/logistic-pro/  # MinIO API через nginx
curl https://io.logistgo.pro/console/       # MinIO Console через nginx
```

---

**Итого: порт 443 - внешний (для приложения), порты 9000/9001 - внутренние (для nginx). Это стандартная схема работы через reverse proxy!** ✅
