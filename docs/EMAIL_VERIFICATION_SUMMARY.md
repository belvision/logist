## 🚀 Что нужно сделать для запуска

### 1️⃣ Применить миграцию к базе данных

**Выполните в PostgreSQL:**

```bash
cd apps/backend
psql -d ваша_база_данных -f drizzle/0003_add_email_verification.sql
```

Или вручную выполните SQL:

```sql
ALTER TABLE "users" ADD COLUMN "email_verification_token" text;
ALTER TABLE "users" ADD COLUMN "email_verified_at" timestamp;
```

### 2️⃣ Настроить SMTP (опционально)

Если хотите, чтобы письма реально отправлялись, добавьте в `.env` файл бэкенда:

```env
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=ваш-email@gmail.com
SMTP_PASSWORD=ваш-пароль-приложения
SMTP_FROM="LogistGo.pro <noreply@logistgo.pro>"
```

**Если SMTP не настроен**, ссылки для подтверждения будут выводиться в консоль бэкенда (удобно для разработки).

### 3️⃣ Перезапустить серверы

```bash
# Backend
cd apps/backend
npm run dev

# Frontend  
cd apps/frontend
npm run dev
```

## 📋 Как это работает

### Сценарий 1: Новая регистрация

1. Пользователь регистрируется на сайте
2. **Автоматически:**
   - Создается учетная запись
   - Генерируется токен подтверждения
   - Отправляется письмо на email (или ссылка в консоль)
3. Пользователь получает доступ к личному кабинету
4. В личном кабинете видит **желтый баннер** с предупреждением:

```
⚠️ Подтвердите ваш email
Ваш email не подтвержден. Некоторые функции сайта будут ограничены...
[📧 Отправить письмо повторно]
```

### Сценарий 2: Подтверждение email

1. Пользователь открывает письмо
2. Кликает по ссылке подтверждения
3. Открывается страница `/verify-email`
4. Видит сообщение:
   - 🔄 "Подтверждение email..." (пока проверяется)
   - ✅ "Email подтвержден!" (успех)
   - ❌ "Ошибка подтверждения" (истек срок/неверный токен)
5. При успехе автоматически перенаправляется на `/login` через 3 секунды

### Сценарий 3: Работа в личном кабинете

**До подтверждения:**
- Баннер с предупреждением вверху страницы
- Можно закрыть баннер (скроется до следующей сессии)
- Можно отправить письмо повторно

**После подтверждения:**
- Баннер исчезает
- Полный доступ ко всем функциям

## 🧪 Тестирование

### 1. Проверьте миграцию

```sql
-- Должны появиться новые колонки
SELECT column_name, data_type 
FROM information_schema.columns 
WHERE table_name = 'users' 
AND column_name IN ('email_verification_token', 'email_verified_at');
```

### 2. Зарегистрируйте тестового пользователя

1. Откройте `/registry`
2. Зарегистрируйтесь
3. **Проверьте консоль бэкенда** - там должна быть ссылка:

```
📧 SMTP not configured. Verification link: http://localhost:3000/verify-email?token=eyJh...
```

### 3. Проверьте личный кабинет

1. После регистрации попадете в личный кабинет
2. **Вверху страницы** должен быть желтый баннер:
   - Иконка предупреждения
   - Текст о неподтвержденном email
   - Кнопка "Отправить письмо повторно"

### 4. Подтвердите email

1. Скопируйте ссылку из консоли бэкенда
2. Откройте в браузере
3. Должна открыться страница `/verify-email`
4. Должно появиться сообщение "Email успешно подтвержден!"
5. Автоматическое перенаправление на `/login`

### 5. Проверьте после подтверждения

1. Войдите снова в личный кабинет
2. **Баннера больше не должно быть**

## 📊 Проверка в БД

-- Посмотреть статус пользователя
SELECT 
  id_user,
  email,
  email_verified_at,
  CASE 
    WHEN email_verified_at IS NOT NULL THEN 'Подтвержден'
    ELSE 'Не подтвержден'
  END as status
FROM users
WHERE email = 'test@example.com';

## 🆘 Если что-то не работает

### Баннер не показывается
- Проверьте консоль браузера на ошибки
- Убедитесь, что `email_verified_at` = NULL в БД
- Проверьте, что импорт `EmailVerificationBanner` добавлен в `AppLayout`

### Письмо не приходит
- **Это нормально!** Если SMTP не настроен
- Ссылка для подтверждения будет в консоли бэкенда
- Скопируйте и откройте ее вручную

### Ошибка при подтверждении
- Проверьте, что токен не истек (7 дней)
- Убедитесь, что миграция применена
- Проверьте консоль бэкенда на ошибки
