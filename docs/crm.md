# CRM Module API Documentation

## A) Общее

### Назначение CRM модуля

CRM модуль предназначен для управления контрагентами (компаниями-партнерами) в рамках workspace. Модуль поддерживает:
- Управление контрагентами (carrier/перевозчики и customer/заказчики)
- Автозаполнение данных по УНП (из налоговой Беларуси и DaData)
- Управление контактами контрагентов
- Управление автомобилями контрагентов
- Управление водителями и их привязкой к контрагентам и автомобилям
- Настройку порядка полей формы (drag&drop)
- Пользовательские поля и их значения

### Базовый префикс

Все роуты CRM модуля имеют префикс: `/api/crm`

Модуль разделен на три подмодуля:
- **Companies** (`/api/crm/companies/*`) — контрагенты, контакты, custom fields/values, field prefs
- **Vehicles** (`/api/crm/vehicles/*`) — автомобили, vehicle-drivers
- **Drivers** (`/api/crm/drivers/*`) — водители, company-drivers

### Как определяется контекст workspace

`workspace_company_id` определяется автоматически для каждого пользователя через функцию `getUserCompany(userId)`, которая возвращает компанию пользователя из таблицы `users_company`. 

**Важно:** Пользователь должен состоять хотя бы в одной компании. Если пользователь не состоит ни в одной компании, все запросы вернут ошибку `400` с сообщением "Пользователь не состоит ни в одной компании".

Все операции в CRM ограничены `workspace_company_id` текущего пользователя. Пользователь видит и может работать только с данными своего workspace.

### Как работает авторизация

Все роуты CRM требуют авторизации через middleware `authenticate`.

**Заголовки:**
- `Authorization: Bearer <token>` (приоритет)
- Или cookie `auth_token`
- Или cookie `access_token`

**Токен:**
- JWT токен, который проверяется через `verifyAccessToken(token)`
- После успешной проверки payload сохраняется в контексте Hono: `c.set('user', payload)`

**Извлечение userId:**
В контроллерах используется функция:
```typescript
function getUserId(c: any): string | null {
  const userCtx = c.get('user');
  return userCtx?.id ?? userCtx?.id_user ?? null;
}
```

**Проверка доступа:**
После получения `workspace_company_id` проверяется членство пользователя в workspace через `isUserInCompany(userId, workspace_company_id)`. Если пользователь не является членом workspace, возвращается ошибка `403` с сообщением "У вас нет доступа к этому workspace".

### Общий формат ответов

#### Успешный ответ

**Создание (201):**
```json
{
  "company": { ... }  // или "vehicle", "driver", "contact", "field"
}
```

**Получение одного объекта (200):**
```json
{
  "company": { ... }  // или "vehicle", "driver", "contact"
}
```

**Получение списка (200):**
```json
{
  "data": {
    "items": [...],
    "total": 100,
    "limit": 20,
    "offset": 0
  }
}
```
или
```json
{
  "drivers": [...],  // для списков водителей
  "vehicles": [...], // для списков автомобилей
  "contacts": [...], // для списков контактов
  "fields": [...],    // для списков custom fields
  "values": [...]     // для списков custom values
}
```

**Успешное удаление/привязка (200):**
```json
{
  "message": "Контрагент успешно удалён"
}
```

**Field Prefs (200):**
```json
{
  "prefs": {
    "version": 1,
    "fields": [...]
  }
}
```

#### Ошибка

**Формат ошибки:**
```json
{
  "error": "Текст ошибки"
}
```

**Ошибка валидации (400):**
```json
{
  "error": "Некорректные данные",
  "details": {
    "fieldErrors": { ... },
    "formErrors": [...]
  }
}
```

**Коды ошибок:**
- `400` — Некорректные данные / Пользователь не состоит ни в одной компании
- `401` — Требуется авторизация / Недействительный токен авторизации
- `403` — У вас нет доступа к этому workspace
- `404` — Ресурс не найден (контрагент, автомобиль, водитель, контакт, поле)
- `409` — Конфликт (например, водитель уже привязан)
- `500` — Внутренняя ошибка сервера

### Общие правила пагинации и фильтров

**Пагинация (только для списка контрагентов):**
- `limit` — количество записей (по умолчанию 20, минимум 1, максимум 100)
- `offset` — смещение (по умолчанию 0, минимум 0)
- Ответ содержит: `items`, `total`, `limit`, `offset`

**Фильтры для списка контрагентов:**
- `kind` — тип контрагента: `carrier` или `customer`
- `trust_type` — уровень доверия: `new`, `unverified`, `reliable`
- `search` — поиск по названию или УНП (LIKE поиск)
- `unp` — точный поиск по УНП

**Сортировка:**
- Контрагенты: по `created_at` DESC (новые сначала)
- Водители: по `full_name` ASC
- Автомобили: по `created_at` DESC
- Контакты: по `name` ASC

## B) Quick Start (типовые UI-флоу)

### 1. Создание/редактирование компании с автозаполнением по УНП

**Сценарий:** Пользователь создает нового контрагента, вводит УНП, система автоматически заполняет поля.

**Последовательность вызовов:**

1. **Проверка УНП (опционально, для предпросмотра):**
   ```
   GET /api/crm/companies/autofill?unp=123456789
   ```
   Ответ: `{ "data": { "name_company": "...", "ur_address": "...", "phone": "...", "email": "...", "site": "..." } }`

2. **Создание контрагента:**
   ```
   POST /api/crm/companies
   Body: {
     "kind": "carrier",
     "trust_type": "new",
     "unp": "123456789",  // опционально, но если указан — автозаполнение
     "name": "Название",   // опционально, если есть УНП
     "legal_address": { ... },
     "postal_address": { ... },
     "payment_terms": { ... },
     "bank_details": { ... },
     "note": "..."
   }
   ```
   **Логика автозаполнения:**
   - Если передан `unp`, система запрашивает данные из налоговой Беларуси или DaData
   - Автозаполняются: `name`, `legal_address`, `postal_address` (из `ur_address`, `phone`, `email`, `site`)
   - **Приоритет:** пользовательские значения имеют приоритет над автозаполненными
   - Если `name` не указан и автозаполнение не сработало, вернется ошибка `400`

3. **Редактирование контрагента:**
   ```
   PATCH /api/crm/companies/{id}
   Body: {
     "unp": "123456789",  // при обновлении УНП также срабатывает автозаполнение
     "name": "...",
     ...
   }
   ```

### 2. Управление автомобилями компании

**Сценарий:** Пользователь создает автомобиль для контрагента, просматривает список, обновляет, удаляет.

**Последовательность вызовов:**

1. **Создание автомобиля:**
   ```
   POST /api/crm/vehicles
   Body: {
     "id_crm_company": "uuid",
     "plate_number": "1234 AB-1",
     "brand": "Mercedes",
     "model": "Actros",
     "year": 2020,
     "vin": "WDB12345678901234",
     "note": "..."
   }
   ```

2. **Получение списка автомобилей контрагента:**
   ```
   GET /api/crm/companies/{id}/vehicles
   ```
   Ответ: `{ "vehicles": [...] }` (сортировка по `created_at` DESC)

3. **Получение одного автомобиля:**
   ```
   GET /api/crm/vehicles/{id}
   ```

4. **Обновление автомобиля:**
   ```
   PATCH /api/crm/vehicles/{id}
   Body: {
     "plate_number": "...",
     "brand": "...",
     ...
   }
   ```

5. **Удаление автомобиля:**
   ```
   DELETE /api/crm/vehicles/{id}
   ```

### 3. Управление водителями: быстрый выбор

**Сценарий:** Пользователь выбирает водителя для автомобиля. Система предлагает иерархию списков.

**Последовательность вызовов:**

1. **Создание водителя (если нужно):**
   ```
   POST /api/crm/drivers
   Body: {
     "full_name": "Иванов Иван Иванович",
     "phone": "+375291234567",
     "email": "ivanov@example.com",
     "note": "..."
   }
   ```

2. **Выбор водителя для автомобиля (иерархия списков):**

   **Вариант A: Водители конкретного автомобиля (самый быстрый список):**
   ```
   GET /api/crm/vehicles/{vehicleId}/drivers
   ```
   Если список не пуст — используем его.

   **Вариант B: Водители контрагента (если список автомобиля пуст):**
   ```
   GET /api/crm/companies/{companyId}/drivers
   ```
   Если список не пуст — используем его.

   **Вариант C: Все водители workspace (резервный список):**
   ```
   GET /api/crm/drivers
   ```

3. **Привязка водителя к автомобилю:**
   ```
   POST /api/crm/vehicles/{vehicleId}/drivers/{driverId}
   ```
   **Важно:** При привязке водителя к автомобилю система **автоматически создает связь водитель ↔ контрагент** (в `crm_company_drivers`), если её еще нет. Это гарантирует, что водитель всегда привязан к контрагенту, если он привязан к хотя бы одному автомобилю контрагента.

4. **Привязка водителя к контрагенту (без автомобиля):**
   ```
   POST /api/crm/companies/{companyId}/drivers/{driverId}
   ```

5. **Отвязка водителя:**
   ```
   DELETE /api/crm/vehicles/{vehicleId}/drivers/{driverId}  // от автомобиля
   DELETE /api/crm/companies/{companyId}/drivers/{driverId}  // от контрагента
   ```

### 4. Управление контактами компании

**Сценарий:** Пользователь добавляет контактные лица для контрагента.

**Последовательность вызовов:**

1. **Создание контакта:**
   ```
   POST /api/crm/companies/{id}/contacts
   Body: {
     "name": "Петров Петр",
     "phone": "+375291234567",
     "email": "petrov@example.com",
     "position": "Менеджер",
     "note": "..."
   }
   ```

2. **Получение списка контактов:**
   ```
   GET /api/crm/companies/{id}/contacts
   ```
   Ответ: `{ "contacts": [...] }` (сортировка по `name` ASC)

3. **Удаление контакта:**
   ```
   DELETE /api/crm/companies/{id}/contacts/{contactId}
   ```

### 5. Настройки полей формы (field-prefs) и кастомные поля

**Сценарий:** Пользователь настраивает порядок полей через drag&drop и создает пользовательские поля.

**Последовательность вызовов:**

1. **Получение текущих настроек полей:**
   ```
   GET /api/crm/field-prefs?kind=carrier
   ```
   Ответ: `{ "prefs": { "version": 1, "fields": [...] } }`
   Если настройки отсутствуют, возвращается структура по умолчанию: `{ "version": 1, "fields": [] }`

2. **Сохранение настроек после drag&drop:**
   ```
   PUT /api/crm/field-prefs?kind=carrier
   Body: {
     "version": 1,
     "fields": [
       { "key": "name", "type": "string", "active": true, "order": 10 },
       { "key": "unp", "type": "string", "active": true, "order": 20 },
       ...
     ]
   }
   ```
   **Важно:** Сервер автоматически нормализует порядок:
   - Сортирует поля по `order`
   - Пересчитывает `order` с шагом 10: 10, 20, 30, ...
   - **Фронт должен использовать ответ сервера как источник правды**, не сохранять локально исходный `order`

3. **Получение списка пользовательских полей:**
   ```
   GET /api/crm/custom-fields?kind=carrier
   ```
   Ответ: `{ "fields": [...] }`

4. **Создание пользовательского поля:**
   ```
   POST /api/crm/custom-fields
   Body: {
     "kind": "carrier",
     "key": "custom_field_1",
     "label": "Дополнительное поле",
     "type": "text",  // или "number", "date", "select", "boolean"
     "options": [     // обязательно, если type="select"
       { "value": "option1", "label": "Опция 1" },
       { "value": "option2", "label": "Опция 2" }
     ]
   }
   ```

5. **Получение значений пользовательских полей для контрагента:**
   ```
   GET /api/crm/companies/{id}/custom-values
   ```
   Ответ: `{ "values": [{ "id_value": "...", "id_field": "...", "value": {...}, "field": {...} }] }`

6. **Сохранение значений пользовательских полей (batch upsert):**
   ```
   PUT /api/crm/companies/{id}/custom-values
   Body: {
     "values": [
       { "id_field": "uuid", "value": "текст" },  // для text
       { "id_field": "uuid", "value": 123 },       // для number
       { "id_field": "uuid", "value": "2024-01-01" },  // для date
       { "id_field": "uuid", "value": "option1" },     // для select
       { "id_field": "uuid", "value": true }           // для boolean
     ]
   }
   ```
   **Важно:** Старые значения для указанных полей удаляются перед вставкой новых.

## C) Полное описание всех роутов

### Контрагенты (Companies)

#### POST /api/crm/companies

**Описание:** Создает нового контрагента (carrier или customer) в рамках текущего workspace. Поддерживает автозаполнение по УНП.

**Auth:** Требуется (`authenticate` middleware)

**Request Body:**
```json
{
  "kind": "carrier" | "customer",  // обязательно
  "trust_type": "new" | "unverified" | "reliable",  // обязательно
  "name": "string",  // опционально, но обязательно если нет unp
  "unp": "string (9 символов)",  // опционально, для автозаполнения
  "legal_address": {  // опционально, JSONB
    "country": "string",
    "index": "string",
    "address": "string",
    "phone": "string",
    "email": "string (email)",
    "fax": "string",
    "site": "string (url)"
  },
  "postal_address": {  // опционально, JSONB (та же структура)
    ...
  },
  "payment_terms": {  // опционально, JSONB
    "credit_limit": "number",
    "payment_deferral": "number (int, min 0)"  // дни отсрочки
  },
  "bank_details": {  // опционально, JSONB
    "iban": "string",
    "bic": "string",
    "swift": "string",
    "bank_name": "string",
    "account_number": "string",
    "inn": "string",
    "kpp": "string",
    "rs": "string",
    "ks": "string"
  },
  "note": "string"  // опционально
}
```

**Валидация:**
- `kind` — enum: `carrier` или `customer`
- `trust_type` — enum: `new`, `unverified`, `reliable`
- `name` — минимум 1 символ, максимум 255 символов (обязательно, если нет `unp`)
- `unp` — ровно 9 символов
- `legal_address.email` и `postal_address.email` — валидный email
- `legal_address.site` и `postal_address.site` — валидный URL
- `payment_terms.payment_deferral` — целое число, минимум 0

**Response (201):**
```json
{
  "company": {
    "id_crm_company": "uuid",
    "workspace_company_id": "uuid",
    "created_by": "uuid",
    "kind": "carrier",
    "trust_type": "new",
    "name": "Название компании",
    "unp": "123456789",
    "legal_address": { ... },
    "postal_address": { ... },
    "payment_terms": { ... },
    "bank_details": { ... },
    "note": "...",
    "created_at": "2024-01-01T00:00:00.000Z",
    "updated_at": "2024-01-01T00:00:00.000Z"
  }
}
```

**Ошибки:**
- `400` — Некорректные данные / Поле name обязательно для заполнения / Пользователь не состоит ни в одной компании
- `401` — Требуется авторизация
- `403` — У вас нет доступа к этому workspace
- `500` — Не удалось создать контрагента

#### GET /api/crm/companies/autofill

**Описание:** Выполняет поиск информации о компании по УНП через внешние сервисы (налоговая Беларуси, DaData) и возвращает данные для предзаполнения формы.

**Auth:** Требуется

**Query Params:**
- `unp` (обязательно) — УНП компании (9 символов)

**Response (200):**
```json
{
  "data": {
    "name_company": "ООО Пример",
    "legal_address": {
      "address": "г. Минск, ул. Примерная, 1",
      "phone": "+375291234567",
      "email": "example@example.com",
      "site": "https://example.com"
    },
    "postal_address": {
      "address": "г. Минск, ул. Примерная, 1",
      "phone": "+375291234567",
      "email": "example@example.com",
      "site": "https://example.com"
    }
  }
}
```

**Ошибки:**
- `400` — Параметр 'unp' обязателен
- `401` — Требуется авторизация
- `404` — Компания с таким УНП не найдена

**Примечание:** Система сначала пробует запросить данные из налоговой Беларуси (`grp.nalog.gov.by`), если недоступна — использует DaData (`suggestions.dadata.ru`). Требуется переменная окружения `DADATA_TOKEN` для работы с DaData.

#### PATCH /api/crm/companies/:id

**Описание:** Обновляет данные контрагента. Поддерживает автозаполнение по УНП при обновлении. Пользовательские значения имеют приоритет.

## D) DTO / Типы данных

### CompanyDTO

```typescript
{
  id_crm_company: string;  // UUID, обязательное
  workspace_company_id: string;  // UUID, обязательное
  created_by: string;  // UUID, обязательное
  kind: "carrier" | "customer";  // обязательное
  trust_type: "new" | "unverified" | "reliable";  // обязательное
  name: string;  // обязательное, min 1, max 255
  unp: string | null;  // опционально, 9 символов
  legal_address: LegalAddress | {};  // JSONB, по умолчанию {}
  postal_address: PostalAddress | {};  // JSONB, по умолчанию {}
  payment_terms: PaymentTerms | {};  // JSONB, по умолчанию {}
  bank_details: BankDetails | {};  // JSONB, по умолчанию {}
  note: string | null;  // опционально
  created_at: Date;  // обязательное
  updated_at: Date;  // обязательное
}
```

**LegalAddress:**
```typescript
{
  country?: string;
  index?: string;
  address?: string;
  phone?: string;
  email?: string;  // валидный email
  fax?: string;
  site?: string;  // валидный URL
}
```

**PostalAddress:** (та же структура, что LegalAddress)

**PaymentTerms:**
```typescript
{
```

**BankDetails:**

```typescript
  bank_name?: string;
  account_number?: string;
  inn?: string;  // для СНГ
```

### FieldPrefsDTO

```typescript
{
  version: number;  // обязательное, int
  fields: FieldPrefDTO[];  // обязательное, массив
}
```

**FieldPrefDTO:**
```typescript
{
  key: string;  // обязательное
  type: string;  // обязательное
  active: boolean;  // обязательное
  order: number;  // обязательное, int (нормализуется сервером: 10, 20, 30, ...)
}
```

**Важно:** После сохранения через PUT, сервер нормализует `order` (сортирует и пересчитывает с шагом 10). Фронт должен использовать ответ сервера как источник правды.

### CustomFieldDTO

```typescript
{
  id_field: string;  // UUID, обязательное
  workspace_company_id: string;  // UUID, обязательное

  type: "text" | "number" | "date" | "select" | "boolean";  // обязательное
  options: CustomFieldOption[];  // опционально, но обязательно если type="select"
  created_at: Date;  // обязательное
```

**CustomFieldOption:**
```typescript
{
  value: string;  // обязательное
  label: string;  // обязательное
}
```

### CustomValueDTO

```typescript
{
  id_value: string;  // UUID, обязательное
```

**При получении через GET /api/crm/companies/:id/custom-values, также возвращается информация о поле:**

```typescript
    key: string;
    label: string;
    type: "text" | "number" | "date" | "select" | "boolean";
    options: CustomFieldOption[];
  };
}
```

## Найдены проблемы / TODO

При анализе кода не обнаружено критических проблем. Все роуты подключены, middleware применяется корректно, валидация работает.

**Замечания:**
1. В ответе `POST /api/crm/companies` (строка 2332 в openapi.ts) указано `"vehicle"` вместо `"company"` — это опечатка в документации OpenAPI, в реальном коде возвращается `"company"`.
2. Все операции ограничены `workspace_company_id`, что обеспечивает изоляцию данных между workspace.
