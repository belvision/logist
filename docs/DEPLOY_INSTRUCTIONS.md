# Инструкция по правильному деплою с PM2

> **Важно:** Проект использует именованные адреса `0.0.0.0` вместо `localhost` для обеспечения совместимости между локальной разработкой и продакшеном. Подробнее см. [NAMED_ADDRESSES_CONFIGURATION.md](./NAMED_ADDRESSES_CONFIGURATION.md).

## Проблема дублирования процессов

Если вы видите ошибки `EADDRINUSE` (порт уже используется), это означает что у вас запущено несколько экземпляров приложений на одних портах.

## Правильный порядок деплоя

### 1. Очистка старых процессов

```bash
# Остановить все процессы PM2
pm2 stop all

# Удалить все процессы из PM2
pm2 delete all

# Очистить логи
pm2 flush

# Проверить что процессы удалены
pm2 list
```

### 2. Запуск через ecosystem.config.js

```bash
# Перейти в корень проекта
cd /var/www/logistgo/data/www/logistgo.pro/logistgo-next

# Создать папку для логов
mkdir -p logs

# Запустить приложения через конфигурацию
pm2 start ecosystem.config.js

# Проверить статус
pm2 list
pm2 logs --lines 20
```

### 3. Сохранить конфигурацию PM2

```bash
# Сохранить текущую конфигурацию для автозапуска
pm2 save

# Настроить автозапуск при перезагрузке сервера
pm2 startup
```

## Команды для управления

```bash
# Перезапуск всех приложений
pm2 restart ecosystem.config.js

# Перезапуск конкретного приложения
pm2 restart logistgo-backend
pm2 restart logistgo-frontend

# Просмотр логов
pm2 logs
pm2 logs logistgo-backend
pm2 logs logistgo-frontend

# Мониторинг
pm2 monit

# Статус
pm2 list
```

## Структура портов

- **Frontend (Next.js)**: порт 3000
- **Backend (Hono API)**: порт 5555

## Важные замечания

1. **Всегда используйте ecosystem.config.js** для запуска - это предотвратит дублирование
2. **Не запускайте процессы вручную** через `pm2 start npm` без конфигурации
3. **Проверяйте порты** перед запуском: `netstat -tlnp | grep -E ":(3000|5555)"`
4. **Используйте уникальные имена** для процессов PM2

## Диагностика проблем

```bash
# Проверить занятые порты
netstat -tlnp | grep -E ":(3000|5555)"

# Найти процессы по имени
ps aux | grep -E "(node|tsx)" | grep -v grep

# Убить процесс по порту (если нужно)
sudo lsof -ti:3000 | xargs kill -9
sudo lsof -ti:5555 | xargs kill -9
```

## Если что-то пошло не так

1. Остановите все процессы PM2: `pm2 delete all`
2. Убейте все Node.js процессы: `pkill -f node`
3. Проверьте что порты свободны
4. Запустите заново через ecosystem.config.js
