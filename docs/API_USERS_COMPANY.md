# API для управления пользователями компании

## Обзор

Реализован гибридный подход для добавления пользователей в компанию:

1. **Поиск существующего пользователя** (приоритетный) - ищем по email и сразу добавляем
2. **Приглашение по email** (дополнительно) - отправляем приглашение для регистрации

## Endpoints

### 1. Добавить существующего пользователя в компанию

**POST** `/company/:companyId/users`

Добавляет уже зарегистрированного пользователя в компанию по email.

**Права доступа:** Владелец или Администратор компании

**Тело запроса:**
```json
{
  "email": "user@example.com",
  "role": "Администратор" // или "Пользователь"
}
```

**Ответы:**
- `200` - Пользователь успешно добавлен
- `400` - Некорректные данные
- `401` - Требуется авторизация
- `403` - Недостаточно прав
- `404` - Пользователь не найден (предложить приглашение)
- `409` - Пользователь уже участник компании

### 2. Пригласить пользователя в компанию

**POST** `/company/:companyId/invite`

Отправляет приглашение пользователю для регистрации и присоединения к компании.

**Права доступа:** Владелец или Администратор компании

**Тело запроса:**
```json
{
  "email": "newuser@example.com",
  "role": "Пользователь",
  "message": "Добро пожаловать в нашу компанию!" // опционально
}
```

**Ответы:**
- `200` - Приглашение отправлено
- `400` - Некорректные данные
- `401` - Требуется авторизация
- `403` - Недостаточно прав
- `409` - Пользователь уже зарегистрирован (предложить добавление)

### 3. Получить список пользователей компании

**GET** `/company/:companyId/users`

Возвращает список всех пользователей компании с их ролями.

**Права доступа:** Любой участник компании

**Ответы:**
- `200` - Список пользователей
- `401` - Требуется авторизация
- `403` - Нет доступа к компании

### 4. Удалить пользователя из компании

**DELETE** `/company/:companyId/users/:userId`

Удаляет пользователя из компании.

**Права доступа:** Владелец или Администратор компании

**Ограничения:**
- Владелец не может удалить сам себя

**Ответы:**
- `200` - Пользователь удален
- `400` - Владелец не может удалить сам себя
- `401` - Требуется авторизация
- `403` - Недостаточно прав
- `404` - Пользователь не найден в компании

### 5. Изменить роль пользователя

**PUT** `/company/:companyId/users/:userId/role`

Изменяет роль пользователя в компании.

**Права доступа:** Только Владелец компании

**Тело запроса:**
```json
{
  "role": "Администратор" // или "Пользователь"
}
```

**Ограничения:**
- Владелец не может изменить свою роль
- Роль "Владелец" нельзя назначить через API

**Ответы:**
- `200` - Роль обновлена
- `400` - Некорректная роль или попытка изменить свою роль
- `401` - Требуется авторизация
- `403` - Только владелец может изменять роли
- `404` - Пользователь не найден в компании

## Роли в компании

- **Владелец** - полные права, может управлять всеми пользователями и ролями
- **Администратор** - может добавлять/удалять пользователей, но не может изменять роли
- **Пользователь** - базовые права доступа к компании

## Рекомендации по использованию

### Для быстрого добавления существующих пользователей:
```bash
curl -X POST /company/123e4567-e89b-12d3-a456-426614174000/users \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email": "existing@user.com", "role": "Пользователь"}'
```

### Для приглашения новых пользователей:
```bash
curl -X POST /company/123e4567-e89b-12d3-a456-426614174000/invite \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email": "new@user.com", "role": "Пользователь", "message": "Добро пожаловать!"}'
```
